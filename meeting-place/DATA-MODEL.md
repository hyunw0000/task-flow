# 데이터 모델

- 출처: [PRD.md](PRD.md) 7·8장, [DECISIONS.md](DECISIONS.md) D-004·D-009·D-010·D-012·D-013, [ARCHITECTURE.md](ARCHITECTURE.md) 4장
- 저장소는 SQLite 파일 하나(`meeting-place/backend/data/meetingplace.db`)다. 시작할 때 테이블이 없을 때만 만든다.
- 구조: `모임 → 참가자(마지막 위치) → 후보 → 투표`, 그리고 외부 API 캐시.
- 시각은 UTC ISO 8601 문자열로 저장한다. 좌표는 위도 `lat`, 경도 `lng` (실수).

## 1. meetings (모임)

| 필드 | 뜻 | 필수 | 규칙 |
| --- | --- | --- | --- |
| `id` | 링크에 쓰는 모임 번호. 무작위 10자 | 자동 | 추측하기 어려워야 한다. 바꿀 수 없다. |
| `name` | 모임 이름 | 필수 | 1~30자, 앞뒤 공백 제거 (BR-01) |
| `situation` | `lunch` · `dinner` · `second` | 필수 | 세 값만 허용 (BR-04) |
| `status` | `open` · `decided` · `ended` | 자동 | 처음 `open`. 한 방향으로만 바뀐다. |
| `locked` | 새 참가 막기 (0/1) | 자동 | 처음 0. 모임장만 바꾼다. (BR-19) |
| `pivot_name` | 기준 지점 이름(역 이름 등) | 선택 | 계산 전에는 비어 있다. |
| `pivot_lat`, `pivot_lng` | 기준 지점 좌표 | 선택 | 계산 전에는 비어 있다. |
| `pivot_pinned` | 모임장이 기준 지점을 고정했는가 (0/1) | 자동 | 처음 0 (BR-15) |
| `decided_candidate_id` | 확정된 후보 | 선택 | `status`가 `decided`일 때만 값이 있다. |
| `created_at` | 만든 시각 | 자동 | |
| `expires_at` | 만료 시각 | 자동 | `created_at + 24시간` (D-009) |

## 2. participants (참가자)

| 필드 | 뜻 | 필수 | 규칙 |
| --- | --- | --- | --- |
| `id` | 참가자 번호(정수) | 자동 | |
| `meeting_id` | 속한 모임 | 필수 | 모임이 지워지면 함께 지운다. |
| `name` | 표시 이름 | 필수 | 1~20자, 앞뒤 공백 제거. 같은 모임 안에서 겹치면 거부 (BR-03) |
| `token_hash` | 참가 토큰의 해시 | 필수 | 토큰 원문은 저장하지 않는다. (D-004) |
| `is_host` | 모임장 여부 (0/1) | 자동 | 모임당 정확히 한 명 |
| `sharing` | 위치 공유 동의 중 (0/1) | 자동 | 처음 0 (BR-05) |
| `lat`, `lng` | 마지막 위치 | 선택 | `sharing`이 0이면 반드시 비어 있다. (BR-09) |
| `accuracy_m` | 위치 오차(미터) | 선택 | |
| `located_at` | 마지막 위치를 받은 시각 | 선택 | 오래됨 판단에 쓴다. (BR-06) |
| `removed` | 모임장이 내보냄 (0/1) | 자동 | 1이면 모든 요청을 거부하고 다시 참가할 수 없다. (D-013) |
| `joined_at` | 참가 시각 | 자동 | |

## 4. votes (투표)

| 필드 | 뜻 | 규칙 |
| --- | --- | --- |
| `meeting_id` | 모임 | |
| `participant_id` | 투표한 사람 | 모임당 사람마다 한 행만 있다. (유일 제약 `meeting_id + participant_id`) |
| `candidate_id` | 고른 후보 | 투표를 바꾸면 이 값을 덮어쓴다. 후보가 지워지면 투표도 지운다. |

## 5. cache_entries (외부 API 캐시)

| 필드 | 뜻 | 규칙 |
| --- | --- | --- |
| `key` | 질의를 나타내는 문자열 | 예: `places:{lat3}:{lng3}:{카테고리}`, `transit:{출발}:{도착}` (좌표는 소수 셋째 자리로 뭉쳐 같은 질의로 본다) |
| `value` | 응답 JSON | |
| `expires_at` | 유효 기한 | 지나면 쓰지 않고 새로 받는다. 종류별 기한은 BR-21. |

참가자·모임 정보는 캐시에 넣지 않는다. 참가자의 정확한 좌표는 캐시 키에 쓰지 않고, 소수 셋째 자리(약 100m)로 뭉친 좌표만 쓴다.

## 6. 삭제 규칙

| 시점 | 지우는 것 |
| --- | --- |
| 참가자가 공유를 끈다 | 그 참가자의 `lat`·`lng`·`accuracy_m`·`located_at` (BR-09) |
| 모임이 확정되거나 끝난다 | 모든 참가자의 위치 (D-009) |
| 모임장이 끝낸다 | 모임과 하위 데이터 전부 |
| `expires_at`이 지난다 | 모임과 하위 데이터 전부. 서버가 주기적으로 정리한다. |
| 캐시 `expires_at`이 지난다 | 해당 행 |

## 7. 필드 이름이 문서마다 같은 뜻으로 쓰인다

| 용어 | 뜻 |
| --- | --- |
| 모임 | `meetings` 한 행 |
| 참가자 | `participants` 한 행. 모임장도 참가자다. |
| 기준 지점 | 모임의 `pivot_*`. 모두에게 가장 공평하다고 계산된 곳 |
| 후보 | `candidates` 한 행. 추천 목록에서 올린 장소 |
| 추천 | 기준 지점 주변에서 불러온 장소 목록. 저장하지 않고 요청마다 만든다. |
