# AGENTS.md

미팅플레이스 저장소에서 사람과 AI 에이전트가 함께 따르는 규칙이다.

## 프로젝트

- 한 줄 설명: 모임 사람들이 서로의 위치를 실시간으로 보면서, 모두에게 가까운 곳 주변의 밥집·술집을 찾아 투표로 정하는 웹 앱이다. 메인 기능은 주변 밥집·술집 찾기와 실시간 위치 공유이고, 거리 공평성은 기본 기능이다.
- 기획 원본: [../MEETING-PLACE-PLAN.md](../MEETING-PLACE-PLAN.md)
- 요구사항: [PRD.md](PRD.md)
- 진행 순서: [WORKFLOW.md](WORKFLOW.md)

## 기술 스택

- 화면: React · Vite
- API: FastAPI
- 저장소: SQLite
- 지도와 장소: 카카오맵 JS SDK, 카카오 로컬 API. 평점과 영업시간은 Google Places API (New).
- 이동시간: ODsay 또는 TMAP 대중교통

## 작업 규칙

1. **문서 먼저**: PRD에 없는 기능은 코드를 쓰기 전에 PRD부터 고친다.
2. **계획 먼저**: 구현 전에 무엇을 바꿀지 적고, 사용자가 확인한 뒤 코드를 쓴다.
3. **작게 나눈다**: 이슈 하나가 브랜치 하나, PR 하나다.
4. **확인한 것만 완료라고 한다**: 테스트를 돌리거나 직접 실행해 본 결과를 근거로 쓴다. 못 해 본 것은 못 했다고 적는다.
5. **모르면 묻는다**: 근거 없는 가정은 PRD의 열린 질문(Q-xx)에 적는다.

## 보안과 개인정보

- API 키는 서버(FastAPI)에만 둔다. 카카오맵 JS 키만 브라우저에 두고 도메인 제한을 건다.
- `.env`와 키 파일은 커밋하지 않는다. 키 이름만 `.env.example`에 적는다.
- 네이버·카카오 지도 화면을 크롤링하지 않는다. 공식 API만 쓴다.
- 위치 정보는 참가자가 동의해야 다른 참가자에게 보인다. 동의 기본값은 꺼짐이다.
- 모임이 끝나면 위치 데이터를 지운다. 보관 기간은 PRD의 Q-04에서 정한다.

## Git 규칙

- 기본 브랜치는 `main`이다. `main`에 직접 커밋하지 않는다.
- 브랜치 이름: `feature/<주제>`, `fix/<주제>`, `docs/<주제>`
- 커밋 메시지: `<종류>: <한국어 요약>` (종류는 feat, fix, docs, refactor, test, chore)
- PR 설명에는 바뀐 점, 확인한 방법, 남은 문제를 적는다.
- 병합은 리뷰 뒤에 하고, 마일스톤이 끝나면 태그를 단다.

## 문서 표기

- R-xxx: 수락한 요구사항, A-xx: 가정, Q-xx: 열린 질문, D-xxx: 결정
- 문서는 한국어로 쓴다. 코드의 식별자는 영어로 쓴다.
