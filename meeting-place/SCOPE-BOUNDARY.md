# 범위 경계

- 출처: [PRD.md](PRD.md) 6·7장
- 목적: 사람과 AI 에이전트가 PRD 밖의 기능을 추가하지 않게 한다. 이 표에 없는 기능은 만들지 않는다. 만들고 싶으면 PRD부터 고친다. ([AGENTS.md](AGENTS.md) 작업 규칙 1)

## 1. 이번에 구현한다 (Must)

| ID | 기능 | 한 줄 경계 |
| --- | --- | --- |
| R-001 | 모임 만들기 | 이름과 상황(점심·저녁·2차)만 받는다. 날짜·시간·장소 입력은 없다. |
| R-002 | 참여와 동의 | 이름 입력 + 위치 공유 동의. 동의 기본값은 꺼짐이다. |
| R-003 | 실시간 위치 공유 | 화면이 켜져 있는 동안만 보낸다. 위치 이력은 쌓지 않는다. |
| R-004 | 공유 중지 | 끄면 서버의 마지막 위치도 지운다. |
| R-005 | 기준 지점 계산 | 대중교통 이동시간 기준. 지하철역·번화가 후보 5~10곳 중에서 고른다. |
| R-006 | 주변 밥집·술집 찾기 | 기준 지점 주변 카테고리별 목록. 거리·평점·영업 여부를 보여 준다. |
| R-007 | 상황 프리셋 | 점심·저녁·2차 세 가지만 있다. 사용자 정의 프리셋은 없다. |
| R-008 | 공통 거리 표시 | 지도 위 거리·이동시간 표시. 경로선 그리기는 하지 않는다. |
| R-009 | 후보 투표 | 후보 올리기, 1인 1표, 만든 사람이 확정한다. |
| R-010 | 링크 공유 | 링크 복사까지. 카카오톡 공유 버튼은 Later다. |

## 2. 나중에 한다 (Later)

[PRD.md](PRD.md) 7장의 Later 표와 같다. 백그라운드 위치 공유, 환승 횟수 반영, 모임 재사용, 자동차 이동시간, 카카오톡 공유 버튼.

## 3. 하지 않는다 (Non-goal)

| 항목 | 이유 |
| --- | --- |
| 회원가입·로그인 | 1차는 링크를 아는 사람이 참가한다. (A-03) |
| 예약·결제·리뷰 작성 | 정하는 데까지만 돕는다. |
| 네이티브 앱 | 웹으로 시작한다. |
| 채팅 | 카카오톡 같은 기존 채팅방을 쓴다. |
| 위치 이력 저장·이동 경로 재생 | 개인정보 부담이 크다. (A-06) |
| 지도·리뷰 크롤링 | 약관 위반이다. 공식 API만 쓴다. |
| 푸시 알림 | 네이티브·서비스 워커 작업이 따른다. |

## 3-1. 기술 쪽 금지

- 상태 관리 라이브러리(Redux 등), CSS 프레임워크, ORM을 들이지 않는다. React 기본 기능, 일반 CSS, `sqlite3` 직접 사용으로 시작한다. ([DECISIONS.md](DECISIONS.md) D-002)
- Docker, 배포 자동화, 외부 DB를 1차에서 만들지 않는다.
- API 키를 프런트엔드에 두지 않는다. 카카오맵 JS 키만 예외다.

## 4. 경계에서 헷갈리기 쉬운 것

| 상황 | 판단 |
| --- | --- |
| 위치 공유를 거부한 사람이 출발지를 직접 입력하게 하고 싶다 | 1차에 없다. PRD Q-13에서 정한다. |
| 후보를 장소 검색 없이 직접 이름으로 올리고 싶다 | 하지 않는다. 추천 목록에서만 후보로 올린다. |
| 투표 마감 시간을 두고 싶다 | 하지 않는다. 만든 사람이 확정한다. |
| 모임을 끝낸 뒤 다시 열고 싶다 | 하지 않는다. 새 모임을 만든다. |
