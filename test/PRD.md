# PRD: 카드형 Task 관리 웹 앱

- 출처: [PRODUCT-DIRECTION.md](PRODUCT-DIRECTION.md), [PROJECT-DISCOVERY.md](PROJECT-DISCOVERY.md)
- ID 표기: R-xxx 는 수락한 요구사항, F-xx 는 확인한 사실, A-xx 는 가정, Q-xx 는 열린 질문이다. F · A · Q 번호는 PROJECT-DISCOVERY.md 의 번호를 그대로 쓴다.

## 1. 한 문장 설명

혼자 일을 관리하는 개인이 할 일을 카드로 등록하고, 카드마다 지금 어떤 상태인지 한눈에 보는 웹 앱이다. (F-01, F-07)

## 2. 사용자와 상황

- **사용자**: 혼자 일을 관리하는 개인이다. (F-07)
- **사용 방식**: 자기 컴퓨터에서 앱을 실행하고 브라우저로 쓴다. (F-02, F-05)
- **로그인**: 없다. 팀 기능도 없다. (F-08)
- **실행 환경**: 화면은 React · Vite, API 는 FastAPI, 저장소는 SQLite 다. (F-04)
- **화면 크기**: 정하지 않았다. → Q-15

## 3. 목표

- 해야 할 일을 카드로 등록하고 고치고 지울 수 있다. (F-01, F-12)
- 카드마다 지금 어떤 상태인지 한눈에 볼 수 있다. (F-01)
- 상태는 사용자가 직접 정한다. (F-11)

## 4. 카드 정보와 상태 규칙

### 카드 정보

| 정보 | 필수 여부 | 규칙 | 근거 |
| --- | --- | --- | --- |
| 제목 | 필수 | 길이 제한: 정하지 않음 → Q-08 | F-09 |
| 설명 | 정하지 않음 → Q-01 | 길이 제한: 정하지 않음 → Q-08 | F-09 |
| 상태 | 필수 | 아래 상태 규칙을 따른다. | F-09, F-10 |

### 상태 규칙

- 상태는 **할 일 · 진행 중 · 완료**, 세 가지다. (F-10)
- 카드 한 장의 상태는 한 번에 하나다. (F-09, F-10)
- 상태는 사용자가 직접 고른다. 자동으로 바뀌지 않는다. (F-11)
- 새 카드의 처음 상태: 정하지 않았다. → Q-02
- 상태를 옮기는 순서에 제한이 있는지: 정하지 않았다. → Q-03
- 상태 세 가지가 고정인지: 고정이라고 가정한다 (A-04). 확인 필요 → Q-12

## 6. 사용자 스토리와 완료 조건

완료 조건에는 확인한 사실과 수락한 요구사항에서 나오는 것만 적었다. 정하지 않은 동작은 열린 질문 번호로 표시했다.

### R-001 카드 등록

> 혼자 일을 관리하는 사람으로서, 해야 할 일을 카드로 남겨 두고 싶다. 그래야 그 일을 관리할 수 있다.

- [ ] 제목과 설명을 입력해 등록하면 새 카드가 생긴다.
- [ ] 제목이 비어 있으면 카드가 등록되지 않는다. (이때 사용자에게 무엇을 보여 줄지 → Q-11)
- [ ] 등록한 카드가 상태별 보기(R-003)에 보인다.
- 정하지 않음: 설명을 비워도 되는지 (Q-01), 처음 상태 (Q-02), 길이 제한 (Q-08)

### R-002 상태 변경

> 혼자 일을 관리하는 사람으로서, 카드의 상태를 직접 바꾸고 싶다. 그래야 일이 어디까지 왔는지 기록할 수 있다.

- [ ] 카드의 상태를 할 일 · 진행 중 · 완료 가운데 하나로 바꿀 수 있다.
- [ ] 바꾼 상태가 상태별 보기(R-003)에 바로 반영된다.
- [ ] 사용자가 바꾸지 않으면 상태는 바뀌지 않는다.
- 정하지 않음: 순서 제한 (Q-03), 화면에서 바꾸는 방법 (Q-04)

### R-003 상태별 보기

> 혼자 일을 관리하는 사람으로서, 카드를 상태별로 나누어 보고 싶다. 그래야 카드마다 지금 어떤 상태인지 한눈에 알 수 있다.

- [ ] 모든 카드가 할 일 · 진행 중 · 완료 별로 나뉘어 보인다.
- [ ] 카드 한 장은 자기 상태 쪽에 한 번만 보인다.
- 정하지 않음: 보기 모양 (Q-05), 같은 상태 안의 카드 순서 (Q-06), 카드에 보여 줄 정보 (Q-16), 카드 수 규모 (Q-13), 화면 크기 (Q-15)

### R-004 카드 수정

> 혼자 일을 관리하는 사람으로서, 이미 만든 카드의 제목과 설명을 고치고 싶다. 그래야 틀렸거나 바뀐 내용을 바로잡을 수 있다.

- [ ] 카드의 제목과 설명을 고쳐 저장하면 바뀐 내용이 보인다.
- [ ] 제목을 비운 채로는 저장되지 않는다. (이때 사용자에게 무엇을 보여 줄지 → Q-11)
- 정하지 않음: 수정할 때 상태도 함께 고칠 수 있는지 (Q-09), 설명을 비워도 되는지 (Q-01), 길이 제한 (Q-08)

### R-005 카드 삭제

> 혼자 일을 관리하는 사람으로서, 필요 없어진 카드를 지우고 싶다. 그래야 관리할 카드만 남길 수 있다.

- [ ] 카드를 지우면 상태별 보기(R-003)에서 사라진다.
- 정하지 않음: 지우기 전에 확인을 받는지, 지운 카드를 되살릴 수 있는지 (Q-07)

### R-006 카드 저장 유지

> 혼자 일을 관리하는 사람으로서, 앱을 다시 열어도 전에 만든 카드를 보고 싶다. 그래야 할 일을 이어서 관리할 수 있다.

- [ ] 브라우저를 닫았다 다시 열어도 카드와 그 상태가 그대로 있다.
- [ ] 앱을 껐다 다시 실행해도 카드와 그 상태가 그대로 있다.
- [ ] 등록(R-001) · 상태 변경(R-002) · 수정(R-004) · 삭제(R-005)한 결과가 다시 열었을 때도 그대로 있다.
- 정하지 않음: 같은 컴퓨터에서 탭을 여러 개 열어 쓰는 경우 (Q-14)
